# 01 · 系统架构与任务设计

## 数据链路

```
检测（ESP32-S3, 10~15Hz） → 传输（USART3 帧协议） → 解析（esp32linkTask）
     → 滤波（distTask） → 控制（gimbalTask PID, 50Hz） → 执行（SG90×2）
                                    → 显示（oledTask）/ 上云（esp8266Task）
```

## 任务划分

| 任务 | 优先级 | 栈(words) | 周期 | 职责 |
|------|--------|-----------|------|------|
| esp32linkTask | Normal | 512 | 事件驱动 | USART3 字节出队 → 拼帧 → 解析更新目标状态 |
| gimbalTask | Normal | 256 | 20ms | PID 计算 + 舵机 PWM 输出 |
| distTask | BelowNormal | 256 | 50ms | 距离滑动平均滤波，维护"有人"判定 |
| oledTask | BelowNormal | 256 | 100ms | OLED 刷新目标状态与距离 |
| esp8266Task | BelowNormal | 512 | 周期上报 | MQTT + JSON 上报云平台 |
| ledTask | Low | 128 | 500ms | 系统心跳 + 健康巡检 |

## 关键机制

**队列解耦中断与任务**：USART3 接收中断只做"字节入队 + 重挂接收"，解析全部在任务侧完成，保证 15Hz 数据流不丢帧。

**共享状态单写者**：目标状态 `g_target{dx, dy, dist_mm, has_target, last_ms}` 仅由 esp32linkTask 写入，其余任务只读，避免竞态。

**健康打卡巡检**：每个任务周期调用 `mod_alive(id)` 刷新心跳计数，ledTask 巡检各模块心跳并映射到独立 LED，实现任务级故障定位。

**链路超时判活**：1s 内无新检测帧即判定目标丢失，OLED 显示 NO、云台缓慢回中，防止 ESP32 断链后残留旧状态。
